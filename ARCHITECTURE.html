🏛️ System Architecture

The application is built on a modern three-tier architecture with clear separation of concerns.

Browser (Port 3000)
⇅
FastAPI Server (Port 8001)
⇅
JSON Mock Data

Frontend Layer

Vue 3 single-page application with reactive components, client-side routing, and global state management via composables. Communicates with backend via Axios HTTP client.

API Layer

FastAPI REST endpoints for inventory, orders, demand forecasts, and spending analytics. Includes flexible filtering, data validation via Pydantic, and CORS support for cross-origin requests.

Data Layer

In-memory mock data loaded from JSON files at startup. No database—data lives in memory for the session. Perfect for demos and prototyping.

Key Architectural Patterns

  • Composition API: Vue 3 components use the Composition API for better code organization
  • Composables for State: Global state via useFilters, useAuth, useI18n composables (not Vuex/Pinia)
  • Centralized API Client: All backend communication through /client/src/api.js
  • Pydantic Validation: All API responses validated with Pydantic models
  • Mock Data Strategy: Load JSON at startup, in-memory for entire session

🔄 Data Flow

Request/Response Cycle

1. User Action → User clicks filter or navigates to view
2. Filter Update → useFilters composable updates state
3. API Call → Component calls api.getFoo(getCurrentFilters())
4. Backend Process → Endpoint applies filters, validates with Pydantic
5. Data Filtering → Filters applied to in-memory JSON data
6. Response → JSON response returned to frontend
7. Render → Component updates reactive data, Vue re-renders template

Global State Flow

Filter State (useFilters)

State Variables:

  • selectedPeriod
  • selectedLocation (warehouse)
  • selectedCategory
  • selectedStatus

Shared by: All views simultaneously

User State (useAuth)

Data: Profile, tasks, preferences

Used by: ProfileMenu, TasksModal

Language State (useI18n)

Data: Current locale, translations, currency

Persisted in: localStorage ('app-locale')

📡 API Endpoints

Inventory

GET /api/inventory?warehouse=X&category=Y

Returns inventory items filtered by warehouse and/or category

Orders

GET /api/orders?warehouse=X&category=Y&status=Z&month=M

Returns orders with multi-dimensional filtering. Month supports both direct (2025-01) and quarter format (Q1-2025)

Dashboard

GET /api/dashboard/summary?warehouse=X&category=Y&status=Z&month=M

Returns KPI summary: inventory value, low stock count, pending orders, backlog items

Demand & Backlog

GET /api/demand
GET /api/backlog

Demand forecasts and backlog items (no filtering)

Spending Analytics

GET /api/spending/summary
GET /api/spending/monthly
GET /api/spending/categories
GET /api/spending/transactions

Financial analytics and transaction history

Query Parameters (All Filters)

Parameter Values Default
warehouse San Francisco, London, Tokyo all
category Circuit Boards, Sensors, Actuators, Controllers, Power Supplies all
status Delivered, Shipped, Processing, Backordered all
month 2025-01 to 2025-12 or Q1-2025 to Q4-2025 all

⚙️ Backend Structure

Main Components

main.py

FastAPI application definition with all endpoint functions. Handles filtering logic, CORS setup, and request routing.

mock_data.py

Loads JSON files at startup and initializes in-memory data structures for inventory, orders, demand, backlog, and spending.

server/data/*.json

Mock data files: inventory, orders, demand_forecasts, backlog_items, purchase_orders, spending, transactions.

Data Models (Pydantic)

InventoryItem

SKU, name, category, warehouse, quantity_on_hand, reorder_point, unit_cost, location

Order

Order number, customer, items, status, dates, total_value, warehouse, category

DemandForecast

Item SKU, current/forecasted demand, trend, period

BacklogItem

Order reference, quantity needed/available, days delayed, priority, purchase order link

PurchaseOrder

Supplier, quantity, cost, expected delivery, status, backlog item reference

Filtering & Validation

All requests validated with Pydantic. Filters applied sequentially without mutating original data.

  • apply_filters() — Filter by warehouse, category, status
  • filter_by_month() — Support direct months and quarters (Q1-2025)
  • Case-insensitive category matching
  • CORS enabled for development (allow_origins=["*"])

🔍 Key Architectural Insights

No Database

All data is in-memory JSON. Changes don't persist—restart reloads from files. Perfect for prototyping and demos.

Composable State

Global state via lightweight composables (useFilters, useAuth, useI18n) instead of heavy store libraries like Vuex.

Filter-Driven UI

All views watch the same filter state. Changing one filter instantly updates all views with fresh data from the backend.

Type Safety

Pydantic models ensure type safety on backend. All responses validated before reaching frontend.

Internationalization

EN/JA support with auto-currency selection (USD/JPY). Locale persisted to localStorage.

Mock Data at Scale

100+ orders, 50+ inventory items, 3 warehouses, 5 categories—realistic demo data without complexity.
